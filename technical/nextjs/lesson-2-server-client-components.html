Lesson 2 — Server vs Client Components

L2 Next.js Series · Lesson 2 of 5

Next.js App Router defaults to Server Components. Understanding the boundary — and when to cross it — is the single most important architectural decision in App Router applications.

Server Components (Default)

In App Router, every component is a Server Component by default. Server Components:

  • Render on the server — HTML is generated and sent to the browser
  • Ship zero JavaScript to the client
  • Can use async/await directly for data fetching
  • Can access server-only resources (filesystem, DB, secrets)
  • Cannot use React hooks or browser APIs
// app/blog/page.tsx — Server Component (no directive = default)
import { db } from '@/lib/db'

export default async function BlogPage() {
  const posts = await db.query.posts.findMany()
  return (
    <ul>{posts.map(post => <li key={post.id}>{post.title}</li>)}</ul>
  )
}

'use client' Directive

Add 'use client' at the top of a file to make it a Client Component. The component's entire module graph becomes part of the client bundle.

'use client'
import { useState } from 'react'
import { useSearchParams } from 'next/navigation'

export default function SearchBox() {
  const [query, setQuery] = useState('')
  const searchParams = useSearchParams()
  return <input value={query} onChange={e => setQuery(e.target.value)} />
}

Browser APIs (window, localStorage)✗✓

Shipped to browser JS bundle✗✓
Interactive event handlers✗✓

Composing Server and Client

Pass Server Component output as children into Client Components — without crossing the boundary the wrong way.

// Client Component wrapper
'use client'
export function CardShell({ children }: { children: React.ReactNode }) {
  return <div className="card">{children}</div>
}

// Server Component — fetches data, passes to Client Component as children
import { CardShell } from '@/components/CardShell'

export default async function Dashboard() {
  const data = await fetchDashboard()
  return (
    <CardShell>
      <DashboardStats data={data} />
    </CardShell>
  )
}
Key insight: You can pass components (not just primitives) as children props. The Server Component renders first, then its HTML output is passed into the Client Component — the boundary is not crossed.

Context Providers

React Context only works in Client Components. Wrap a Client Component provider around Server Component content:

// app/providers.tsx
'use client'
export function Providers({ children }: { children: React.ReactNode }) {
  return <ThemeProvider>{children}</ThemeProvider>
}

// app/layout.tsx
import { Providers } from './providers'
export default function RootLayout({ children }) {
  return <html><body><Providers>{children}</Providers></body></html>
}

Hydration

Client Components are rendered twice: on the server (initial HTML), then on the client (React hydrates to attach event listeners). If the server HTML doesn't match the client render, you get a hydration mismatch.

Rule: Keep data-fetching on the server. Only push interactivity to Client Components. This eliminates hydration bugs and reduces bundle size.
