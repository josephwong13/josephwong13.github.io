Lesson 4 — Next.js 15 Breaking Changes

L4 Next.js Series · Lesson 4 of 5

Next.js 15 (October 2024) ships two major breaking changes: async request APIs and updated caching defaults. Upgrade with the codemod first.

Upgrade: npm install next@latest react@rc react-dom@rc or
npx @next/codemod@canary upgrade latest

Async Request APIs

APIs that access request-specific data are now async. This is the biggest migration step.

APINext.js 14Next.js 15
cookies()cookies().get('x')(await cookies()).get('x')
headers()headers().get('x')(await headers()).get('x')
params (page/layout)params.slug(await params).slug
searchParams (page)searchParams.page(await searchParams).page
// Next.js 14 — synchronous (broken in Next.js 15)
import { cookies } from 'next/headers'
export default function AdminPanel() {
  const cookieStore = cookies()       // ← throws
}

// Next.js 15 — async (correct)
export default async function AdminPanel() {
  const cookieStore = await cookies()
  const token = cookieStore.get('token')
}

Run the automated codemod to update everything at once:

npx @next/codemod@canary next-async-request-api .

New Caching Defaults

Three things that were cached by default are now uncached by default:

What changedNext.js 14 defaultNext.js 15 defaultRestore with
fetch() requestsCached (force-cache)Not cached (no-store){ cache: 'force-cache' }
GET Route HandlersCachedNot cachedexport const dynamic = 'force-static'
Client Router CachestaleTime = 30sstaleTime = 0staleTimes.dynamic in next.config.ts
// next.config.ts — restore Next.js 14 client router cache behavior
import type { NextConfig } from 'next'
const nextConfig: NextConfig = {
  experimental: {
    staleTimes: { dynamic: 30 },
  },
}
export default nextConfig
Silent breakage risk: Next.js 14 cached fetch by default — many apps never specified caching and worked by accident. Next.js 15 changes this. Audit fetch calls and add explicit { cache: 'force-cache' } where data should be cached.

Production: Next.js 15 still uses Webpack for production builds. Turbopack for production is in beta.

Other Notable Changes

  • React 19: App Router uses React 19 RC; Pages Router stays on React 18
  • instrumentation.js stable: onRequestError hook for server lifecycle observability
  • next.config.ts: Full typed config support
  • ESLint 9 support: Auto-applies ESLINT_USE_FLAT_CONFIG=false escape hatch
