Knowledge Bases & RAG

Scenario: The hotel's FAQ used to be hardcoded strings retrieved by keyword match. Responses were stale, inconsistent, and hallucinated room availability. You need to replace it with a proper RAG pipeline — documents in S3, chunked and embedded, stored in a vector database, retrieved and injected into the model's context at query time.

End-to-end RAG pipeline

PIPELINE

Ingest → Embed → Store → Retrieve → Augment

Ingest: documents from S3 (PDF, TXT, CSV, DOCX, HTML).
Chunk: split into overlapping segments (fixed-size, recursive, or semantic).
Embed: Titan Embeddings (or Cohere) converts chunks to vectors.
Store: vectors go into a vector store. Metadata stored alongside.
Retrieve: user query embedded → similarity search → top-K chunks.
Augment: chunks injected as context into the FM prompt.[R6]

Chunking strategies

CRITICAL CONFIG

Chunking strategy affects retrieval quality

Fixed-size (e.g. 512 tokens) — fast, but may split sentences, lose meaning. Use with overlap.
Recursive character split — splits on whitespace/punctuation, preserves semantic units better.
Semantic (embedding-based) — clusters semantically similar sentences together. Best quality but slowest.
Dynamic chunking — adjusts chunk size based on content type (code vs prose).[R6]

TUNING

Chunk size vs context window tradeoff

Larger chunks → more context, higher embedding cost, risk of dilution (unrelated content dilutes the relevant signal). Smaller chunks → more precise retrieval, but may lose cross-sentence meaning. Bedrock KB default is a starting point; tune based on retrieval relevance scores.

Vector stores

VECTOR STORES — D1 SKILL

Bedrock KB native vs third-party

Bedrock Knowledge Base — fully managed. Connects to: OpenSearch Serverless (default), Amazon Aurora (pgvector), Pinecone, MongoDB Atlas. Handles sync, embedding, retrieval.
OpenSearch Serverless — vector search + metadata filtering. Scalable, no infra management.
pgvector on Aurora — SQL query + vector similarity in one. Good for hybrid retrieval (keyword + semantic).
Milvus / Pinecone — purpose-built vector databases. Choose when Bedrock KB doesn't fit.[R6]

Hybrid search and reranking

RETRIEVAL QUALITY

Hybrid search — keyword + semantic

Pure vector search misses exact-term matches (e.g. product codes, brand names). Hybrid combines BM25 keyword scoring with semantic similarity. Bedrock reranker then re-orders the union result set using a cross-encoder for final precision.[R6]

RERANKER

Bedrock reranker — cross-encoder re-ordering

The reranker model scores each retrieved chunk against the original query using a cross-encoder (not a bi-encoder). Produces a re-ranked list optimized for relevance. Typically run as a post-processing step after vector retrieval. Particularly valuable when top-K is large (K > 10).[R6]

Knowledge Base sync strategies

SYNC

Incremental vs full sync

Full sync — re-embed and re-upload all chunks. High cost, full fresh start. Use when embedding model version changes.
Incremental sync — S3 event trigger (new/modified object) → sync only changed chunks. Delta embeddings only. Use for production update pipelines.
Scheduled sync — cron-style re-sync on a schedule. Good for documents that update periodically (menus, inventory).[R6]

Bedrock Flows — visual orchestration

D2 SKILL 2.1.5

Bedrock Flows — no-code orchestration

Bedrock Flows provides a visual node graph for orchestrating multi-step GenAI workflows. Nodes: Prompt, Conditional branch, Knowledge Base retrieve, Lambda transform, human approval. Edges connect outputs to inputs. Used for complex RAG flows, multi-agent coordination, and review/approval workflows.[R10]

Prompt Management

D2 SKILL

Prompt variants, variables, versioning

Prompt Management stores base prompts, injects runtime variables ({{customer_name}}, {{booking_ref}}), and versions them. A/B test prompt variants by routing to different prompt IDs. Compare quality via Bedrock Model Evaluations.[R7]
