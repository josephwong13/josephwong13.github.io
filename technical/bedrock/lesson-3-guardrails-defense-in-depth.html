Guardrails & Defense-in-Depth

Scenario: The hotel-booking agent from Lesson 2 starts returning guest phone numbers and email addresses in its responses. Legal has flagged this as a GDPR violation. You need to add guardrails to the agent — not just a single filter, but a layered safety system that handles input, model inference, and output in sequence.

Guardrail policy components

POLICY LAYER

Content filters — input and output

Bedrock Guardrails evaluates content before FM inference (input filter) and after (output filter). Filters check for: hate speech, violence, sexual content, and harassment. Each filter has a threshold (NONE, LOW, MEDIUM, HIGH). If threshold is exceeded, the request is blocked or the response is redacted.[R5]

POLICY LAYER

Denied topics

Define topics the FM is not allowed to discuss. Guardrails intercepts at the policy layer — not at the model level — so the FM cannot be prompted around the restriction.[R5]

POLICY LAYER

PII masking

Guardrails can detect and mask PII in outputs. Combined with Amazon Comprehend for pre-detection, this is the primary GDPR/HIPAA compliance tool for Bedrock.[R5]

POLICY LAYER

Word filters — custom term blocking

Block specific words or phrases: competitor names, proprietary terms, internal project codenames. Simpler than denied topics — pattern match rather than semantic classification.[R5]

⚠ IAM ENFORCEMENT

bedrock:GuardrailIdentifier — mandatory guardrails via IAM

For org-level enforcement, attach an IAM policy requiring all bedrock:InvokeModel calls to pass through a specific guardrail. This makes guardrails non-bypassable — even API calls that skip agent code hit the constraint.[R5]

Defense-in-depth pipeline

LAYERED ARCHITECTURE — D3 SKILL 3.1.4

Pre-processing → FM → Post-processing

No single layer is sufficient. The exam expects you to draw this pipeline:
Layer 1: Amazon Comprehend — pre-detect PII in the user input.
Layer 2: Bedrock Guardrails — policy-level input evaluation (denied topics, word filters).
Layer 3: FM inference — model generates response.
Layer 4: Guardrails output eval — PII masking, content filtering of response.
Layer 5: Lambda — custom validation (JSON schema enforcement, response length sanity check).
Layer 6: API Gateway — final response filtering before returning to client.[R5]

PII detection and masking

D3 SKILL 3.2.2

Comprehend + Macie for PII detection

Amazon Comprehend — real-time PII detection in user input. Amazon Macie — discovery and classification of PII in S3 data stores. Use Macie to audit what data your Knowledge Base documents contain before enabling retrieval.[R5]

MASKING PATTERN

Guardrails PII redaction

Guardrails can replace detected PII with a placeholder ([EMAIL], [PHONE]). Configure which PII entity types to mask. Applies to outputs; combine with Comprehend pre-filter for complete coverage.[R5]

Governance and model cards

D3 SKILL 3.3.1

Model cards — documented FM limitations

SageMaker model cards record a model's intended use cases, training data summary, performance metrics, and known limitations. Required evidence for compliance frameworks (SOC 2, GDPR). Bedrock's managed models have AWS-published model cards; custom models require your own.[R5]

LINEAGE

AWS Glue — data lineage tracking

Glue Data Catalog registers data sources used in RAG pipelines. CloudTrail audits every InvokeModel call with the principal, timestamp, and input parameters. Together they provide the audit trail required for D3 governance.[R5]

Drift detection and monitoring

D3 SKILL 3.3.4

Semantic drift and bias drift

Semantic drift: model begins returning responses that deviate semantically from expected baseline — measured by embedding similarity between current and golden-output distributions. Bias drift: model's output distribution shifts across demographic groups over time. CloudWatch Anomaly Detection on token embeddings triggers alerts.[R5]

LLM-AS-JUDGE

Automated evaluation with a judge FM

Use a high-capability FM (Opus) to evaluate outputs from a lower-capability FM (Haiku) against a rubric. Score: relevance, factual accuracy, tone. Run nightly on a golden dataset. Detects quality regressions before they reach production.[R5]
