Bedrock APIs & Foundation Model Selection

Scenario: You're building a customer-support chatbot. Your team is debating whether to use the Converse API or the older InvokeModel API, how to choose between Nova and Claude, and whether to use cross-region inference or provisioned throughput. You need a framework — not guesswork.

Four API layers

KEY API

Converse API — the 2026 standard

Unified interface across all Bedrock models that support the messages paradigm. Write once, swap models.[R2]

POST https://bedrock-runtime.us-east-1.amazonaws.com/model/anthropic.claude-3-5-sonnet-20241022-v2:0/invoke

Request shape: messages array (user/assistant roles), inferenceConfig (temperature, topP, maxTokens), optional system prompt.[R2]

API LAYER

InvokeModel — provider-specific, deprecated pattern

Raw JSON body tuned to a specific model's schema. No consistent error surface. Prefer Converse for new code.[R1]

API LAYER

Messages API — streaming-first

Conversational wrapper built on Converse. Supports ConverseStream for real-time token streaming. Best for chat UIs.[R2]

API LAYER

Responses API — newest (2026)

Agentic, tool-aware responses. Handles multi-step reasoning internally. Used by AgentCore under the hood.[R1]

⚠ EXAM PATTERN

Converse vs Invoke — when to pick which

If a question says "write code once and target multiple models" → Converse. If it names a specific model and tuning its native params → InvokeModel.

Inference parameters

Control output shape without changing the model.[R14]

PARAMETERS

Temperature, topP, maxTokens, stopSequences

temperature — randomness. 0 = deterministic (factual), 1 = creative. topP — nucleus sampling pool. Set one, not both.[R14]

maxTokens — hard cap on completion length. Prevents runaway responses in production.[R14]

stopSequences — model stops when it generates any of these tokens. Useful for structured output.[R14]

"inferenceConfig": {
  "temperature": 0.7,
  "topP": 0.9,
  "maxTokens": 2048
}

Foundation model catalog

MODELS

Amazon Nova family (AWS-native)

Nova Micro (text-only, fast, cheap), Nova Lite (multimodal), Nova Canvas (image generation), Nova Reel (video). Trained by AWS; often best price-performance for standard tasks.[R1]

MODELS

Third-party models

Anthropic Claude 3/4, Meta Llama 3/3.1, Mistral Large/Instruct, Cohere Command R+, Google Gemini 1.5/2.0. Choose based on context length, reasoning capability, and cost.[R1]

MARKETPLACE

Bedrock Marketplace — 100+ models[R13]

Access to third-party and open-weight models not in the standard catalog. Deploy to a dedicated endpoint; pricing and latency differ from native Bedrock models. Exam questions about "choosing the right model for a specialized task" often point here.

Inference optimization

THROUGHPUT

Cross-region inference profiles[R12]

Single API endpoint that routes to multiple regions. Increases throughput by distributing load. Does not support Provisioned Throughput. Track costs per-region via CloudWatch.[R12]

CAPACITY

Provisioned Throughput[R15]

Commit to a model unit count for guaranteed throughput. Two types: by Tokens (pay per token) or by Model Units (pay per hour regardless of usage). Used when you need consistent latency at scale.

Model selection framework

EXAM FRAMEWORK

Decision tree for D2 skill 2.2.x

Task complexity? Simple Q&A → Haiku/Nova Micro. Complex reasoning → Opus/Gemini Ultra.
Latency sensitive? Streaming → ConverseStream. Batch → InvokeModel.
Multi-modal? Nova Lite or Claude 3.5.
Cost-constrained? Tiered routing: Haiku for simple, Opus for complex (model cascading).[R1]

PATTERN

Model cascading (Haiku → Opus)

Route each query to the cheapest capable model. Use a classifier or rules engine to determine complexity, then call the appropriate model. Reduces cost 60–80% vs always calling the largest model.[R1]
