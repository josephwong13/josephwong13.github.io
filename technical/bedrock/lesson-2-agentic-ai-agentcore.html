Agentic AI — AgentCore, Action Groups & MCP

Scenario: Your hotel-booking chatbot needs to query room availability, update a reservation, and send a confirmation email — in a single conversation turn. A single model call can't do all three. You need an agent that can plan, use tools, and chain results together. AgentCore is how you build this on AWS.

AgentClassic deprecation → AgentCore

⚠ DEPRECATION

AgentClassic deprecated July 2026

All new agentic workloads must use Bedrock AgentCore. AgentClassic enters maintenance mode and receives no new features.[R3]

ARCHITECTURE

AgentCore — four sub-components[R4]

Harness — orchestration layer, defines agent configuration, prompt, and tools. Runtime — executes the agent loop (think → act → observe → think again). Gateway — API entry point, handles auth and rate limiting. Memory — session state, conversation history, and context management across turns.

Agent orchestration loop

LOOP

Think → Act → Observe (ReAct pattern)

The agent receives a user goal. It thinks ("what tool do I need?"), acts (calls a tool), observes the result, then decides next step. Loop continues until the goal is met or a stop condition fires.[R4]

1. User goal → agent
2. Agent thinks: which tool applies?
3. Agent calls: action group function (Lambda / HTTP)
4. Tool returns: raw result
5. Agent observes: does result satisfy the goal?
6. Yes → respond to user. No → loop to step 2.

Action groups

CORE COMPONENT

action_group — the tool definition[R3]

An action group declares a function (name, description, parameters) that the agent can call. Under the hood, action groups are backed by Lambda (simple, stateless) or Amazon ECS (complex, long-running). The agent decides when to call an action group based on its description.

LAMBDA BACKEND

Lambda as action group executor

Define the function schema in the agent. Lambda receives agent-interaction events with the tool name and parameters. Return a JSON result. Fast cold starts for simple tools.[R4]

MCP

MCP tools — Model Context Protocol[R3]

MCP servers expose tools via a standardized interface. AgentCore can consume MCP tools directly — no per-tool Lambda required. Lambda becomes the MCP server for lightweight tools. ECS hosts MCP servers for complex, stateful ones.

Session management

STATE

Persistent session context

Each conversation turn carries prior context. Memory stores session state (not Lambda state — Lambda is stateless). Configure TTL and max tokens per session to prevent context overflow.[R4]

Multi-agent patterns

D2 SKILL 2.1.1 / 2.1.4

Agent Squad — multiple agents, specialized roles

AWS Agent Squad orchestrates multiple agents. Each agent is specialized: one handles booking, one handles cancellation, one handles refunds. A supervisor agent routes to the right sub-agent. TSTALIASID marks agents in testing mode (no real side effects).[R3]

PATTERN

Step Functions + ReAct

For complex multi-step workflows with human-in-the-loop approval, Step Functions drives the ReAct loop. Lambda enforces stopping conditions, circuit breakers, and timeout. IAM policies set resource boundaries per step.[R3]
