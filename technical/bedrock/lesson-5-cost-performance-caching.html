Cost, Performance & Caching

Scenario: The hotel chatbot goes viral on social media. Traffic spikes 10x. Your CFO wants to cut the Bedrock bill in half without degrading response quality. You need a systematic cost optimization framework — not guesswork. Token efficiency, caching, tiered routing, and throughput configuration are the levers.

Token efficiency

D4 SKILL 4.1.1

Token estimation, compression, and pruning

Token estimation — predict token count before calling the model (avoid 400 errors from context overflow). Tools: Titan Embeddings tokenizer, Bedrock SDK estimate.
Prompt compression — remove redundant context. Use a compression FM or rules-based truncation of repeated examples in few-shot prompts.
Context pruning — aggressively trim old conversation turns when approaching context window limit. Keep recent turns, drop older ones with lower relevance scores.
Response limiting — maxTokens caps the cost ceiling. Set conservatively for the task.[R1]

PRICING

Input vs output token pricing

Bedrock pricing is per-token, input and output priced separately. Output tokens cost more for frontier models (Claude Opus, GPT-5). Minimizing output token waste (verbose system prompts, irrelevant examples) has outsized ROI on output-token-priced models.

Prompt caching (2026 feature)

NEW 2026

Prompt caching — repeated context at near-zero cost

Bedrock caches the system prompt and few-shot examples after the first call. Subsequent calls with identical context reuse the cache — billed as a small cache hit fee vs full input token pricing. Most effective for: long system prompts, repeated instruction templates, RAG context chunks that appear across many queries.[R17]

CACHE HIT STRATEGY

Semantic caching — similarity-based reuse

Unlike deterministic caching (exact request match), semantic caching stores the embedding of a query and returns a cached response when the new query's embedding is within a similarity threshold (e.g. cosine similarity > 0.95). Catches paraphrased versions of the same question. Particularly effective for FAQ-style interactions.[R1]

Tiered model routing

D4 SKILL 4.1.2

Cost-capability tradeoff framework

Route each query to the cheapest model that can handle it reliably:
Haiku / Nova Micro — factual recall, classification, simple extraction. Cost: ~$0.25/M tokens.
Sonnet / Nova Lite — moderate reasoning, summarization, translation. Cost: ~$3/M tokens.
Opus / GPT-5 — complex multi-step reasoning, long documents, creative tasks. Cost: ~$15/M tokens.
A rules engine or lightweight classifier determines which tier. Can reduce cost 60–80% vs always calling the largest model.

ROUTING PATTERN

Model cascading vs simple tiering

Simple tiering: fixed routing rule per query type (classification → Haiku, reasoning → Opus).
Cascading: start cheap, escalate to larger model if confidence is low or task fails. Requires a judge model or confidence threshold. More cost-efficient but adds latency on escalated queries.

Provisioned Throughput and cross-region

CAPACITY

Provisioned Throughput — by Tokens vs by Model Units[R15]

By Tokens: pay per token processed. Good for variable, unpredictable workloads. No idle cost.
By Model Units: pay per hour regardless of utilization. Good for steady, predictable, high-volume traffic. Cheaper at scale (> ~40% utilization threshold).
Note: inference profiles and Provisioned Throughput are mutually exclusive — an inference profile cannot use Provisioned Throughput.

D4 SKILL 4.2.3

Batch inference — offline processing

For non-real-time workloads (report generation, bulk document processing), batch inference runs at lower cost. Submit a batch job, receive results asynchronously. Appropriate when latency tolerance is hours, not seconds. Use with SageMaker for custom models.

Auto-scaling for GenAI traffic

SCALING

GenAI-aware auto-scaling

Token burst patterns — not traditional CPU/memory — drive GenAI capacity. Scale on: BedrockInvocationDuration CloudWatch metric, custom token-throughput ALB target groups, or Bedrock's native throughput metrics. Standard ASG based on EC2 metrics misses the real bottleneck.
